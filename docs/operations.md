# 运维、限制与故障排查

最后核对：2026-10-18。安装和首次启动见[安装与启动](getting-started.md)；本文集中说明长期运行、数据安全、隐私、已知限制和排障。

## 启动、停止与日志

- Windows：`.\scripts\windows\start.ps1 start|stop`；服务在隐藏窗口中后台运行。
- macOS：`./scripts/macos/start.sh start|status|stop`；使用 `nohup` 后台运行，停止前核验 PID、启动时间和可执行文件路径。
- 手动构建：在项目根目录运行 `./bin/novel-reader`；后端按进程工作目录读取 `.env`，并相对工作目录解析 `DATA_DIR` 和 `FRONTEND_DIR`。
- 脚本启动时日志写入 `logs/`；手动前台运行则输出到终端。Windows 和 macOS 脚本会保留调用者工作目录；更新构建前先停止服务。
- 健康检查：`GET /api/health` 返回 `{"status":"ok"}`。公开配置可用 `GET /api/config` 查看，不包含密钥。
- `.env` 只在启动时读取；修改配置后必须重启服务。网页保存的语音并发设置是例外，它写入 SQLite 并立即生效。

## 数据、备份与恢复

```text
data/
  reader.sqlite3       小说、译文、任务、术语和阅读位置
  reader.sqlite3-wal   SQLite 运行时文件（可能存在）
  reader.sqlite3-shm   SQLite 运行时文件（可能存在）
  .instance.lock       数据目录进程锁
  audio/               WAV / FLAC 音频资源
  backups/             迁移前数据库快照
```

备份：

1. 停止服务，确认进程已退出。
2. 复制完整 `DATA_DIR`，包括数据库、WAL/SHM、`audio/` 和 `backups/`。
3. 单独安全保存 `.env`，不要提交到 Git。

恢复：

1. 停止服务。
2. 把完整数据目录放回原位；必要时恢复 `.env`。
3. 启动并检查 `/api/health`、书架和播放。

只复制 `reader.sqlite3` 而忽略仍在使用的 WAL 或音频目录，不能构成完整备份。更改 `DATA_DIR` 会切换到另一套独立数据；同一目录不能同时运行两个进程。

## 单实例与锁

- `DATA_DIR/.instance.lock` 由操作系统文件锁约束；进程退出后自动释放，无需手动删除。
- 同一数据目录启动第二个进程会失败并提示已有服务运行。不要通过删除锁文件绕过。
- macOS 控制脚本使用 `logs/.macos-control.lock/` 目录互斥。如果脚本被强制终止后遗留该目录，先确认没有脚本仍在运行，再用 `rmdir logs/.macos-control.lock` 清理空目录；不要删除用户数据目录。
- 停止 Windows 后台进程会终止进程。数据库事务和原子文件发布保护已完成结果；未完成的远端调用仍可能计费。

## 安全边界

- 默认只监听 `127.0.0.1:8787`，不提供用户认证，也没有内置 TLS。
- Host 校验、同源 `Origin` 校验和 `X-Reader-Request: 1` 写请求标记是基础防护，**不构成身份认证**。
- 对外开放监听前，必须在反向代理或网关层增加认证、TLS、访问控制和网络隔离。不要直接把服务暴露到公网。
- 模型和语音密钥只放在后端环境变量或 `.env`；公开配置不返回密钥，错误消息不回显远端响应正文、请求头或密钥。
- 原文和模型输出按数据渲染，不使用未净化的 HTML 注入。
- 访问日志和错误信息可能包含章节标题或错误上下文；分享日志前先检查敏感内容。

## 隐私与费用

- 原文、译文、术语和朗读文本默认保存在本机 SQLite；音频保存在 `DATA_DIR/audio/`。
- 启用自动翻译或语音时，相关文本会发送到你配置的 LLM / TTS 服务。服务商如何处理、保存或用于训练由其条款决定，本项目无法控制。
- 项目本身没有额外的遥测或上传通道；网络请求只发往配置的模型/语音端点。
- 不使用自动翻译或语音时，可以创建小说、保存原文、填写人工译文、阅读和保存进度。
- 模型调用会产生费用。任务尝试记录中的 `usage` 取决于服务商是否返回；为空不代表没有计费。
- 取消任务会尝试中断当前请求，但不能承诺远端已经停止计费。外部生成不是 exactly-once，崩溃后重试可能再次收费。

## 已知限制

- 单用户、本机优先的设计，没有账户、权限、配额或多租户隔离。
- 每个 `DATA_DIR` 只允许一个服务进程，不适合多实例共享同一数据库。
- 当前没有原文历史版本的恢复界面；历史快照保存在数据库中，恢复需要备份或后续工具。
- 真实模型的翻译质量、读音自然度和供应商兼容性不能由假模型测试证明；变更供应商后应做小样本验收。
- FFmpeg 是可选的：没有它时仍可使用 WAV、纯 Go FLAC 解码和已有缓存，但新的 MP3 响应无法解码，后台 FLAC 压缩也会停用。
- 浏览器自动播放策略可能要求用户再次点击播放器；异步加载音频后不能保证自动开始播放。
- 桌面 Chromium 和 Pixel 7 尺寸由 Playwright 验证；其他浏览器未列入 CI 验证范围。
- 修改提示词、模型或声音后，旧任务和旧缓存可能不再复用；需要重新生成，可能产生额外费用。
- 服务没有内置备份调度；备份需要由用户或外部工具完成。

## 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 网页打不开 | 查看 `logs/` 中的监听地址和端口占用；确认前端已构建并存在于 `FRONTEND_DIR` |
| 修改 `.env` 未生效 | 后端启动时读取配置，重启服务；语音并发设置以网页保存的 SQLite 值为准 |
| 返回 403 | 检查 `Host`、`Origin` 和写请求是否带 `X-Reader-Request: 1`；默认只允许本机访问 |
| 返回 409 | 章节、译文、术语或阅读进度已被其他页面/任务修改；刷新后重试，保留草稿 |
| 翻译失败 | 打开处理记录查看配置、认证、超时或格式错误；成功段落仍保留 |
| 音频未压缩 | 确认 FFmpeg 在 PATH 或 `FFMPEG_PATH`；启动探测成功后才启用压缩，需重启 |
| MP3 响应无法解码 | 安装 FFmpeg；OpenAI WAV、Azure WAV 和带元数据的 PCM 不依赖它 |
| 任务显示中断 | 只有服务重启会标记中断；关闭网页不会停止任务。确认后手动继续或重试 |
| 缓存清理被拒绝 | 有排队或运行中的任务时不允许清理，等待任务结束 |
| 无法启动第二个实例 | 同一 `DATA_DIR` 已有服务运行；不要删除 `.instance.lock` |
| macOS 脚本提示锁目录存在 | 确认没有脚本仍在运行，再清理空的 `logs/.macos-control.lock/` |
| 播放不自动开始 | 浏览器自动播放策略限制；点击播放器继续 |
| 后端修改后没有生效 | Go 没有热重载；重新构建并启动，重启会中断正在运行的模型任务 |
