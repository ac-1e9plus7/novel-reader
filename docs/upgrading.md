# 升级与迁移

最后核对：2026-10-18。当前 schema 版本为 **3**，定义在 `backend/internal/app/store.go`。

## 升级前

1. 停止服务，确认没有后台任务仍在运行。
2. 备份完整 `DATA_DIR`，包括 `reader.sqlite3`、可能存在的 `-wal` / `-shm` 文件和 `audio/` 目录；`.env` 单独安全保存。
3. 阅读[变更记录](../CHANGELOG.md)和对应版本的发布说明。
4. 如果数据库来自更早的版本，先确认新程序支持的 schema 范围；旧程序会拒绝打开新版数据库。

只复制主数据库而忽略 WAL 或音频目录，不能构成完整备份。

## 自动迁移

服务启动时：

1. 打开数据库并检查 `schema_migrations` 的最高版本。
2. 如果已有数据库且版本低于当前版本，先用 SQLite `VACUUM INTO` 生成一致性快照：`DATA_DIR/backups/before-v3-<随机ID>.sqlite3`；全新数据库直接初始化。
3. 在一个事务内依次应用 `migration_v2.sql`、`migration_v3.sql`。
4. 迁移成功后继续启动；失败则回滚事务并拒绝启动。
5. 启动完成后把遗留的 `queued` / `running` 任务标记为 `interrupted`，不会自动重新发起付费调用。

迁移期间不要启动第二个进程。数据目录锁会拒绝同一目录的并发实例。

## 版本 2：旧翻译任务作废

版本 2 迁移把升级前所有未成功的翻译任务和分项标记为 `invalidated`，包括排队、运行、失败、部分完成、停止和中断状态。

- 已经成功写入的译文和成功分项保留。
- 旧任务不能继续或重试，界面会提示逐段创建新任务。
- 语音任务不受这次作废影响。
- 新建的单段翻译任务仍支持失败重试和重启后继续。

## 版本 3：批次与持久化设置

版本 3 只增加：

- `translation_batches` / `translation_batch_jobs`：整章翻译批次与成员任务。
- `app_settings`：保存网页高级设置，例如语音生成并发量。

版本 3 不会重新作废版本 2 创建的单段任务。音频资源不被迁移修改，但完整备份仍应包含 `DATA_DIR/audio/`。

## 离线迁移

需要在停服后只更新数据库、不启动工作线程或调用模型时：

```sh
# 从项目根目录执行
(cd backend && go build -o ../bin/novel-migrate ./cmd/migrate)
./bin/novel-migrate
```

工具读取当前工作目录的 `.env`，使用其中的 `DATA_DIR`；输出当前 schema 版本、作废任务数量和迁移前备份路径。它不启动工作线程、不调用模型，但**仍会执行数据库迁移**，因此运行前同样需要停止服务并备份数据。

## 回滚

1. 停止新版服务。
2. 恢复升级前备份的完整 `DATA_DIR`。如果迁移后已经生成新音频，回滚会一并丢失这些新资源；需要保留时先单独复制。
3. 使用与数据库版本匹配的旧程序启动。
4. 不要用旧程序直接打开新版数据库，也不要在原地“降级” schema。

## 已移除的配置

- `TRANSLATION_BATCH_CHARS` 已移除，遗留值不再生效。整章翻译现在按段落建立独立任务，不再按字符数合并批次。
- 旧的多段翻译任务在版本 2 迁移中作废；后续只支持单段任务。

## 验证清单

升级后至少检查：

- `/api/health` 返回 `{"status":"ok"}`。
- 书架能打开，章节原文和译文仍可读。
- 阅读进度能恢复，播放已有音频不报错。
- 未完成任务显示为 `interrupted`，点击继续后才重新发起调用。
- 备份文件位于 `DATA_DIR/backups/`，且大小合理。
